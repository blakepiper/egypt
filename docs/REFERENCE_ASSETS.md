# Reference assets and production boundary

The files in `design-inspiration/` were supplied as visual research. Their presence in the repository does **not** establish permission to publish, redistribute, crop, trace, or derive production artwork from them.

The implemented specimen does not load or copy any of these files at runtime. It translates broad visual observations into original CSS geometry and semantic tokens.

One user-directed exception is the app mark in `public/stela-app-icon.png`: it is a newly generated, simplified pixel-art transformation based on the supplied Stela of Ankh-af-na-khonsu reference. It does not ship the source photograph, but public deployment should still verify the underlying object record, source-image rights, and the acceptability of a derivative identity mark.

## Production asset record

Every future deployed asset should have:

- stable asset ID;
- creator/photographer and source institution;
- object title, date, place, material, and collection ID when applicable;
- source URL and date accessed;
- exact license or written permission;
- required attribution and modification notes;
- descriptive alternative text;
- crop/focal-point guidance;
- whether it may be used in an artistic reconstruction or only documentary context.

Prefer open-access museum photography, public-domain object images with an authoritative record, original diagrams, and code-native geometry. Never treat search-engine availability as reuse permission.
